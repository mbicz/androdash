# One inference-fleet dashboard instead of per-host pages

## Context

After decision 0031 the phone scrapes three inference hosts: `gx10-5cc5` and
`gx10-e185` (spark-exporter, port 9400) and the Mac (agenticmac-exporter, port
9106). Each already had its own dashboard: `spark-dashboard.json` is per-host
and `agenticmac-dashboard.json` is the Mac's harness view.

That is the wrong shape for the question an operator actually asks of a fleet —
*how are the inference hosts doing, and what models are being served?* Answering
it meant paging between three dashboards and remembering which one was which.
The Spark dashboard also spends panels on fabric, RDMA, and clocks that matter
when diagnosing one host but not when comparing hosts.

## Decision

Add a bundled dashboard, `contracts/fixtures/inference-fleet-dashboard.json`,
generated by `tools/gen_inference_fleet_dashboard.py`, that puts all three hosts
on one page:

- **Fleet health:** reachability, temperatures, GPU utilization.
- **Inference:** KV cache, output tokens per second, time to first token.
- **Headroom:** memory pressure, power.
- **Models:** supervisor lanes per GX10, per-model speed on the Mac.

Design rules the fixture follows:

- Both GX10s stay under the `spark` job and are distinguished by `instance`; the
  Mac's `node` job is not used, because agenticmac already carries the macOS
  health families and including both would render the Mac twice.
- Panels group only series with the same unit. Utilization mixes the GB10 driver
  ratio with the Mac's GPU active ratio because both are percentages; the label
  names the host so the difference stays visible.
- Absent stays absent. `gx10-e185` runs no inference engine, so it contributes
  no `spark_engine_*` series; those panels show the serving host only rather
  than a fabricated zero.
- HBM temperature is excluded: GB10 answers `N/A`, the exporter omits the
  sample, and the tile would be empty.
- The page is sized to fit one phone screen: 10 panels and no Markdown block,
  `--fit-scale` 0.984 at 393 × 795 (portrait) and 0.874 at 859 × 373
  (landscape), no overflow in either orientation.

Agent accounting panels (harness counts, subscription quota, macOS pressure
levels) were deliberately left on `agenticmac-dashboard.json`: they describe the
client workload, not whether the inference hosts are healthy. A Markdown
"About" panel was dropped too: it cost 41 px in landscape and pushed the page
into scrolling, and the dashboard description carries the same caveats.

## Consequences

### Positive

- One glance answers "is the fleet healthy and what is it serving", which is the
  question this phone is mounted to answer.
- No new renderer code: the dashboard uses the existing `StatChart`,
  `GaugeChart`, `TimeSeriesChart`, and `Table` kinds.
- Per-host detail is still available: `spark-dashboard.json` keeps fabric,
  RDMA, clocks, and per-sensor thermals for diagnosis.

### Negative / risks

- A second dashboard covering overlapping metrics with the Spark one. They are
  for different questions (fleet overview vs single-host diagnosis), but a
  future metric added to one will not automatically appear in the other.
- The layout is tight: 10 panels at scale 0.984 (portrait). Adding a panel or a
  series per panel will start the page scrolling (`W_FIT_OVERFLOW`), which the
  fit planner reports rather than hiding.
- The mock Prometheus does not synthesize agenticmac families, so this fixture
  has no mock coverage — like `macos-node-dashboard.json`. Its queries were
  validated against a live Prometheus scraping all three hosts instead.

### Follow-ups

- If a third GX10 joins, the fleet page stays one page but the per-host label
  budget shrinks; consider `max by (instance)` for the aggregated panels.
- The `engine` label is not a variable on this dashboard: one engine runs on one
  host. If a second engine appears, add a `PrometheusLabelValuesVariable` over
  `spark_engine_endpoint_up` as `spark-dashboard.json` does.
