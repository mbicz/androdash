# agenticmac-exporter integration

**Status:** implemented for the Mac host; verified against a live exporter and
Prometheus on 2026-10-28.
**Exporter:** `mbicz/agenticmac-exporter` (separate repository, Python standard
library, launchd user agent).
**Dashboard:** [`agenticmac-dashboard.json`](../../contracts/fixtures/agenticmac-dashboard.json),
generated by [`tools/gen_agenticmac_dashboard.py`](../../tools/gen_agenticmac_dashboard.py)
and bundled in the APK.

## What it shows

AI coding harnesses running on the Mac (omp, opencode, codex, claude, gemini,
cursor-agent, aider) and the macOS readings Darwin node_exporter lacks.

| Panel | Metric family | Notes |
|---|---|---|
| Running agents | `agent_processes{role="interactive"}` | Exact executable matching; `CursorUIViewService` is not Cursor. |
| Active sessions | `agent_sessions_active` | Sessions written within the exporter's active window, for harnesses that are running. |
| Output tokens per second | `agent_tokens_total{type="output"}` | 5m rate per harness. |
| Spend per hour (USD) | `agent_cost_usd_total` | The harness's list-price estimate; subscriptions are not billed this. No currency unit exists in C-005, so the unit is in the title. |
| Requests today by plan | `agent_requests_total{tier}` | `tier` = free / subscription / paid / local / unknown, from the exporter's configurable tier rules (exporter ≥ 0.2.0). |
| Quota used | `agent_quota_used_ratio` | Rate-limit windows recorded by omp, per provider and window. |
| Model speed | `agent_model_output_tokens_per_second` | omp's decayed per-model throughput, top 8. |
| Pressure | `macos_memory_pressure_level`, `macos_thermal_pressure_level` | 0 normal; 1 Elevated; 2+ Critical. |
| Temperature | `macos_soc_temperature_celsius`, `macos_nvme_temperature_celsius` | macmon and smartctl. |
| Agent memory | `agent_process_resident_memory_bytes` | Summed per harness. |
| SoC power | `macos_soc_power_watts` | cpu, gpu, ram, and whole-system (`sys`). |
| Homebrew services / Lima VMs | `macos_brew_service_up`, `macos_lima_vm_running` | 1 = running. |

The title is the host name from `node_uname_info`, so node_exporter must be
scraped too.

## Running it on the phone

The exporter listens on every interface (`listen = "0.0.0.0:9106"` in
`~/.config/agenticmac-exporter/config.toml`), as do node_exporter
(`--web.listen-address=0.0.0.0:9100`) and the Mac's Prometheus (`:9090`), so
the phone can reach them over the LAN or, away from home, over Tailscale (use
the Mac's tailnet address or MagicDNS name as the target host). With the
on-phone collector (decision 0019):

```sh
adb shell am start -n com.mbicz.androdash/.MainActivity \
  --es dashboard_url "http://androdash.local/dashboards/agenticmac-dashboard.json" \
  --ez collector true \
  --es collector_targets "node:mac=192.168.1.20:9100,agenticmac:mac=192.168.1.20:9106" \
  --es layout_mode fit
```

Over Tailscale, replace `192.168.1.20` with the Mac's tailnet address
(`tailscale ip -4`) or MagicDNS name; the phone must be on the same tailnet.

Counters start when the phone first scrapes them, so rates and spend fill in
over the selected time range.

## Privacy

The exporter reads harness databases read-only through column allowlists, never
reads prompt or message text, and exports only bounded labels (`harness`,
`role`, `provider`, `model`, `type`, `window`, `service`, `vm`, `sensor`,
`component`). It has no session, path, account, or email labels. It listens
without authentication on every interface (LAN and tailnet), like node_exporter
and the Mac's Prometheus — keep the Mac's networks trusted;
the collector has no credential support (C-008: no credentials in v1). The
exporter supports basic auth if the collector gains it later.
